## 下一步实施计划

用户已认可下一阶段目标；以下实施顺序与具体闭环是当前建议，落实时对照案件草案与现有代码确认，不声称已经实现。

2. 将该范围写成明确案件数据：开局状态、人物知识、固定答复、调查入口、线索关联及阶段完成条件。先实现这一阶段，不要求先完成全案。
3. 复用已有场景交互，替换技术 Demo 内容。原著是座钟，不是挂钟；区分当前物证、警方已收取的物证和初勘记录。旧 Demo 的纸条正文不能混入案件。
4. 增加最小询问与出示证据流程。先以固定回复验证知识边界和状态变化，再决定接入 AI，避免同时调试剧情和模型。
5. 验收完整路径、刷新恢复、重复请求、信息权限与阶段完成条件。阶段完成不等于全案结案。

首个阶段不提前授予后续验尸庭、霍斯事件及最终取证材料，不冒充完整案件或完整 AI 审讯。

## 持续遵守的建模原则

- 真相、人物误信、对外供述分别存储；虚假供述不必对应真实误信。
- 开放案件内容用语义描述与稳定 ID 关联，不穷举现实犯罪行为。
- 画面没有表现不等于证据不存在；未设定不等于确认不存在。
- 原著未交代的行踪标为未知，不编造不在场证明。
- NPC只掌握当前阶段实际获知的信息；玩家取得线索不等于所有人物自动同步知道。
- 关键结果与状态变更由后端固定规则校验，不能由 AI 临时决定真相。
- 遵循课程规定的代码组织与副作用边界，不因改编剧情任意更换架构。
