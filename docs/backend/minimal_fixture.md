# 最小示例案件与阶段基线

当前目标是验证类型能承载一个可调查示例，不编写正式凶案，也不实现 API。类型契约为 v1.4，示例使用新的 schemaVersion=2；这是 JSON 形状调整，不是旧数据迁移实现。

从项目根目录运行：

```bash
python3 tools/validate_minimal_fixture.py
```

工具只使用 Python 标准库，属于文档契约验证工具，放在 tools/，不是课程 Scala 后端。它读取领域文档的 Scala 类型声明，验证 [示例 JSON](../fixtures/minimal_investigation.json) 的完整 CasePackage 形状、枚举分支、非空集合及本示例使用的引用；不是 Scala 编译器，也不是 Circe 编解码测试。ID／Text 使用字符串，带载荷枚举整体使用 kind 对象；schemaVersion／Revision 等其他包装仍使用声明字段。

一间书房、书桌、抽屉、信件；无人物、犯罪历史、评分题。抽屉外壳可见，内容根节点隐藏，信件自身标记可见：这故意验证“父级隐藏时子级仍不可访问”。打开操作按顺序记录 Open、SetNodeVisible、OperationCompleted；阅读检查记录 Investigated，再以 InformationAcquisition／Acquired 授予线索与事实。事实的主题、来源、入口与路线均有真实引用。

## 本轮最小类型调整

- 增加 AssessmentSpec.InvestigationOnly 与 Scored(requiredIncidents, solution)。仅调查配置不需要伪造参考答案，不能提交指控，也不自动判整案通过。带评分的正式案件仍要求非空答案及必答事件。
- 补节点及父链有效可见性的访问规则，区分空间入口与材料、报告、对话入口。
- 明确 Operation.effects 的顺序、失败原子性和完成记录位置。
- 保留真实 Fact／Topic；未使用的人物、事件等集合为空，而不是把聚合对象替换成空数组。

## 已验证

完整声明结构通过；示例涉及的引用有效；拒绝空线索事实、未知事实、父链循环、不支持的条件、空评分配置和不存在的操作目标。工具对未支持的功能明确拒绝，不返回“发布通过”。

纯内存契约实验验证：初始能访问抽屉外壳但不能直接访问信件；打开后可访问；Investigated 本身不授予知识，Acquired 才更新线索和事实；从同一初始状态重放有序变化得到相同状态。变化数据也按 SessionChange 声明检查。

## 仍待实现验证

无生产 API、数据库事务、鉴权、持久化恢复、请求回执或并发实现。重复请求不重复授予、旧序号不能覆盖新状态、进程重启恢复，必须在后续 Scala 后端切片验证，不能由本工具替代。

场景模型是 fixture: URI 占位符，未制作模型或执行视觉验收。所有节点的局部位置为零只是减少契约夹具复杂度，不是正式布置。内存实验只检查父链访问和知识变化，不模拟距离／网格碰撞、物理或资产加载。正式发布仍须完成资源、关键要求及 sceneFingerprint 对应验收。

## 停止评审与下一步

本轮已具备开始最小实现的类型与数据依据，不再先完成第二轮全部 P0。后续先实现这一条调查路径；每项新能力只在用到前补齐必要契约。权限漏洞、历史一致性、版本与恢复问题随时可修，其他扩展保留待办。

下一条实现路径：初始化绑定修订的状态 → 检查抽屉 → 打开 → 阅读 → 原子写入检查与获知记录 → 重新加载同一知识；同时验证去重、序号冲突与越权入口。API 设计仍见独立草案，正式案情随后确定。
