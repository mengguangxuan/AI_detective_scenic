# 连续事件类型：第一步定义

更新：2026-11-03。本文对应新增 Scala 类型，不表示连续事件引擎、作者上传或发布已经实现。

最新约定：移除案件修订号及历史调查兼容机制；旧调查允许清空。独立验收案直接使用《斑点带子案》。下文未接入运行逻辑的状态不变。

## 范围与入口

案件定义位于 `backend/src/main/scala/services/cases/objects/timeline/`，本局状态位于 `backend/src/main/scala/services/games/objects/timeline/`。`CaseEventId`、`EventPlanId`、`EventObservationId` 位于 cases 的 objects 根目录，与现有 ID 约定一致。

本次只定义纯数据和 Circe codec，没有修改 `CaseContent`、`GameSessionRecord`、现有导入器、数据库或公开接口。新类型尚未注册执行能力，旧案件与旧存档按原协议运行。下一步统一接入新的内容与状态契约，移除案件修订号，不保留旧档迁移和历史行为分支；正常新调查仍须正确恢复。

## 作者定义与本局状态

| 类型 | 职责 |
| --- | --- |
| `CaseTime`、`StoryDuration`、`TimeWindow` | 剧情原点的有符号秒、非负时长、包含端点的已知时间范围 |
| `CaseEvent` | 作者认可的客观事件候选：参与者、对象、地点、工具、经过、结果、因果与事实关联 |
| `CaseTimeline` | 事件定义、初始已发生事件及时间、初始世界快照、未来计划 |
| `EventPlan` | 一个事件的触发、同刻顺序、执行前提、前提不满足时的处理、世界效果和观察安排 |
| `EventRequirements` | 显式条件的合取；不从叙述推断人物能否行动，不拿人物信念当客观状态 |
| `EventWorldEffect` | 有限的世界状态更新协议；新增手法不需要新增犯罪动作枚举 |
| `EventObservation`、`EventDisclosure` | 对指定观察者实际披露的片段、确认事实及完整材料权限 |
| `EventOccurrence` | 本局实际发生的事件、客观时刻和来源，不能整份进入玩家日志 |
| `EventPlanProgress` | 待执行、等待、完成、取消；实际发生时间统一取 occurrence |
| `EventObservationRecord` | 实际获知时刻、接收者及披露内容，不表示相信、承认或向别人转述 |
| `TimelineState` | 本局发生集合、计划进度、世界快照和获知记录；当前时间及序号继续归会话 |

`CaseEvent` 的未来条目是作者预设的候选经过，尚未发生就不能作为本局历史。已发生事件不可改写，条件分支使用不同事件与计划 ID。人物错误记忆、声称时间和虚假供词不得写成 `CaseEvent`；它们仍属于主观资料／证词，不能以本次客观事件类型替代。`causedBy` 只表达客观因果，不隐式授予信息，也不自动构成触发规则。

## 时间与触发语义

- `CaseTime` 允许负值，表示剧情原点之前；不使用模型请求耗时、系统时间或开着网页的时长推剧情。原点标签由案件提供，不能固定解释为周五。
- `TimeWindow` 两端包含，允许单侧未知；完全未知时间留在作者草稿，审核后再形成可执行事件。精确时刻用两端相等表示。codec 拒绝倒置或两端均未知的范围，时长 codec 拒绝负值。
- `At` 在指定时刻尝试；`AfterEvent` 以引用事件的实际发生时间加非负时长计算，引用事件尚未发生则尚未就绪；`When` 在窗口内首次满足前提时尝试，不能自动发生在窗口之外。
- 同刻候选按 `order` 执行，作者校验须拒绝有歧义的同刻顺序或与因果相反的顺序。一个候选执行后，后续候选重新检查最新世界状态；零延迟的后继可在同刻触发。需要检测依赖环及非终止触发链。
- 前提不成立时，`Cancel` 明确取消；`WaitUntil` 仅在截止时间内等待并重新检查。窗口和截止时间共同约束，先到的边界结束等待；在边界时刻按确定顺序完成最后一次检查，再取消。引用事件已取消导致永不就绪的计划，也必须在发布检查或运行进度中显式处理，不能无限挂起。
- 阶段推进可由实际事件或已完成操作表示，本步未再增加一套重复的阶段状态。

## 世界与信息边界

`TimelinePersonState` 明确生命状态、是否受控制及身体实体。人物地点唯一来自该身体实体的 `EntityPlacement`，不再存第二个人物地点。是否受控制是作者／程序设置的执行状态，不代表司法定罪，也不凭对话语气推断。未登记人物状态表示缺配置，不能当作默认活着、自由或不存在。

实体移动同时声明地点、登记节点和相对于该节点父级的坐标。后续执行器须同步实体及表现绑定，检查父链、地点、身体绑定唯一性、冲突节点占用和坐标合法性，防止文字地点与画面分离。开关、解锁和节点可见性仍使用现有会话字段，不能在 TimelineState 另建一份权威副本。

事件发生先更新世界，再判断观察安排。`Direct` 表示作者明确安排的送达／直接观察；`AtPlace` 在该时刻检查接收者的实际地点，不意味着同地点自动看清所有秘密。每份信息仍须由作者审核。模型、前端及客户端不能自行创建获知记录。

`EventDisclosure.text` 是实际可听见／收到的文字，程序不从它解析新事实；`confirmedFacts` 仅包含明确许可的事实。`fullClues` 表示允许收到该材料的完整内容，不能用于片段听闻，也不能把材料关联的全部事实自动授予接收者。一个 NPC 知道某事，不表示相信它或愿意说出。世界事件的 resultingFacts 不自动进入玩家或任何 NPC 知识。

## 后续必须实现的校验与执行

目前只有数据及 codec；除时间范围、时长与 ID 的基础解码约束外，构造 Scala 对象、codec 成功都不等于业务合法。尚未接入以下校验，不能据此发布新案件：

1. ID／引用／接收者／材料权限、唯一性、人物身体和实体表现关联检查。
2. 因果及触发依赖无环；初始发生不晚于开局、计划发生晚于开局；实际时刻处于事件范围；初始历史包含既定前因，历史效果不可重放。
3. 一事件至多一计划；同刻排序、触发窗口、等待截止和互斥分支一致；执行前提不得要求本事件先发生。
4. 世界效果与登记场景能力相符；已有历史不可逆改；前提不成立不擅自补造替代事件。
5. 线索／事实／人物输入中的未来信息门槛；开局知识只能来自已发生历史和实际获知来源。
6. 按时间节点执行的纯计划器、动作生效／中断规则、NPC 上下文版本复核。
7. 短事务内一致保存最终状态、内部发生记录、获知记录、玩家日志与幂等回执；重启后以当前状态恢复，不能再次执行已发生事件。

引擎集成还需要将单记录 `ActionPlan` 改为可承载多个时间节点的提交计划，以及独立的内部事件记录存储；不能把后台谋杀伪装成警方入口上的一次玩家检查。延迟报告可共用推进器，但报告完成和接收者实际获知仍需分别确定。

测试入口：`services.cases.TimelineTypesSuite`。其验证时间编码、引用键、闭合协议、历史／计划分离及实际发生／获知内容的序列化边界，不代表调度、权限执行和真实重启已经验收。
