# 人物对话提示与第一档改进

适用：`vicarage_study/23`，作者对话策略族`interviewPromptVersion: 2`；新问询使用运行模板5，旧冻结模板1—4保留。本批改善语言应对与策略连续性，使用既有历史，不新增心理数值、持久化心理状态或第二个语义裁判。

## 共用与专属内容

所有人物，包括警方，共用[ConversationalInterviewPrompt](../../backend/src/main/scala/services/games/utils/ConversationalInterviewPrompt.scala)。它规定：认知和公开表达分开、候选说法不是依次切换的脚本、可以反问／回避／部分回答、反问后给玩家回答机会、下一轮接住实际回答、普通追问不构成改口理由、实际材料和玩家断言分开、表达长短和少量可见停顿随话题变化。普通合作证人仍可直接回答，不强迫人人怀疑玩家。

专属身份、经历、私人内情、保护目的和对外策略仍放在作者配置的`characters[].dossier`及`voice`，不会把全案真相发给所有人物。NPC只获得自己的材料和对话；警方仍按显式身份取得已完成核查，不因模型一句话就执行搜查、排除嫌疑或逮捕。

新案件可配置`investigation.interviewPromptVersion: 2`复用同一规则。未配置默认1，保留已发布案件和冻结请求原有提示行为；未知版本在发布校验中拒绝。每次问询将实际运行模板版本随上下文冻结，续租重试不改变人物资料或模板版本。作者策略族2继续复用原角色资料；当前在材料阅读基础上修复多轮消息组织与接话，新请求使用运行模板5，现有23无需新建。后续若实质改写共享提示，应发布新的提示版本并保留旧分支，不能直接改写已有冻结请求所选的版本。

## 雷丁与安妮的调整

雷丁初始携枪、独自开枪的对外版本明确放进知识与策略。日常把枪放在书架，与他声称某次放进口袋携来，必须区分；普通询问枪的来源不能让他切换为事后从地上捡枪。收到安妮认罪记录可以引起对她处境与警方依据的试探，但不强制撤供。医学与独立行踪对原供形成实质挑战后，他可以评估坚持、质疑、回避或采用更有利于掩饰的新解释；玩家一句无依据的安全保证不能当成核实事实。

安妮初始对外认罪也不能因普通枪来源追问撤回。她可以询问雷丁的处境，区分玩家的保证与实际记录，并在下一轮接话。具体材料对认罪或枪来源形成挑战时，可解释、坚持或修正，不能把两人写成真实不知共谋、单纯误会对方的无辜者。

这些是对原著策略的游戏改编，不复刻固定章回或保证某个问题必然获得新供。原著第8章维持携枪旧供，第11—12章医学／行踪核查、警方不采信认罪及对安妮处境的确认，和第30章揭示的误导策略，是专属配置依据。出处见[案件文档](murder_at_the_vicarage.md)。

## 记录、固定备用与边界

新版各人物统一输出reply、disclosureIds、statementUpdates三字段；没有版本变化主题的普通证人与警方必须让statementUpdates为空，不能因此更新其他人的说法。旧冻结请求仍按原响应格式。反问直接保存在原问询答复中，通常没有新增材料。下一轮传入本人最近12轮问题与答复，并为所有采用新版提示的人物提供已形成说法摘要。没有新增跨12轮的心理记忆管理；长期担忧、未解问题的独立持久化属于第二档。

人物实际表达的新说法仍按原结构保存与投影，保留旧版材料和首次原文。披露ID从显式白名单选择，引用需来自实际材料；这些结构检查不能判断心理理由是否充分，也不能保证正文始终无矛盾。失败不授予材料，记录原问题；诊断只打印校验标志，不输出模型原文、人物秘密或配置。

固定备用保留可复现路线，但移除“只问枪来源就取得另一版本”的过早入口。雷丁重新说明经过需要实际医学、行踪及安妮陈述作为对照；枪和现场新解释沿已形成的新供继续。它是作者编写的确定性取证路径，不是自由对话必然改口的验收标准。

## 实测方式

真实调用使用后端正常TokenHub配置的DeepSeek，不将密钥放入脚本。作者脚本含取证提示，运行：

```powershell
& 'E:\dev\nodejs\node.exe' tools/verify_character_dialogue_live.mjs
```

脚本覆盖携枪→来源→重复追问、安妮认罪→雷丁反问→玩家不作保证→无依据保证、实际医学／行踪挑战、安妮反问与接话、牧师／玛丽／马普尔／警方，以及安排会面后的男仆、斯通、哈特内尔与阿彻。后四人的安排使用公开API和固定备用准备，不能把准备步骤算作自然语言本身已通过；逐条实际回复仍单独保存与审核。可以加`--redding`、`--anne`、`--others`定向检查；每次保留单独记录，失败不自动重试掩盖。`--restore`在实际重启后核对三组最终完整快照。

无新增说法、结构合法与幂等由脚本检查；是否自然、是否实质改口、是否接住具体反问仍逐条人工审核。不能把“看到安妮口供必须改口”或“每轮必须反问”当成通过标准。完整取证到结案可用`verify_case_completion_live.mjs --dialogue --positive`另验，新缓存与旧版分开。

## 连续接话修复：运行模板5（保留首测模板4）

此前本人最近12条问答已进入单个user JSON的`history`，传输实际只有system与user两条消息。模板4把有效问答按原顺序组成user／assistant轮次，末尾再放本轮资料与问题；不重复把整段历史塞回本轮JSON。新增`dialogueFocus`精确标记最近有效问答和最近一次尝试的状态，不用关键词提取反问，也不把模型摘要当作原文。

共享承接规则要求先理解上一句，再解释“对／为什么／那支枪呢”；玩家说不知道也算作回答。允许谨慎坚持和具体澄清，不以接话为理由自动改口。明确换题按新题答，切人物后只恢复本人的历史。被拒绝或不可用的技术答复不作为assistant台词。

作者风格族仍为2、案件仍为23；新问题冻结模板5，旧模板1—4保持原输入形式及提示。现有23直接继续，无需新局。传输支持可选的`ChatCompletionExchange`对，空历史保持原两条消息和旧输入JSON形状，其他模型业务不自动增加历史。冻结上下文、回执、租约和短事务不变。

不增加额外模型调用、心理数值或摘要压缩。窗口仍是本人最近12条问询，失败占窗口但不冒充有效说话；已登记说法和收到的材料仍作为长期依据，窗口之外普通闲聊、承诺和未解反问暂不保证记住。真实脚本为`tools/verify_dialogue_continuity_live.mjs`，实际重启后加`--restore`核对完整快照；模型语义需逐条审核，协议测试不能替代。

模板4首测能恢复人物自己的话题，但曾将自己的反问归给玩家、将“为什么”接到较早话题。模板5保留模板4分支，再明确user是玩家、assistant是本人，优先承接最近一句，歧义时具体澄清；材料归属高于历史中的转述失误，不靠编造日常经历补足接话。
