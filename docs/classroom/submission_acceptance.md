# 作业测试流程

适用日期：2026-11-01；案件 `vicarage_study/24`。用于验收已运行的项目，包含取证提示。源码结构与当前范围见[README](../../README.md)，演示视频由提交者另行提供。

## 测试准备

1. 确认前后端已启动，打开[首页](http://127.0.0.1:5173/)。源码包不包含运行环境和真实模型密钥，配置参考[验收准备](../frontend/acceptance_preparation.md)。
2. 点“进入案件区”→“查看案件”→“开始新调查”，确认页头为修订24。已有调查可从“我的调查”继续，刷新不会将旧修订升级。
3. 自由问询与推理评审需要可用模型配置；固定问答、检查、采集和警方安排可先验收。不开启模型时，不能将固定路径通过等同于模型能力验收。
4. 保留浏览器身份和数据库，各次新建调查独立保存。

## 主要功能抽查

| 顺序 | 操作 | 预期结果 |
| --- | --- | --- |
| 1：首页与案件区 | 浏览首页、案件详情、人物档案及地点地图 | 导航正常，仅浏览不会取得证据或推进案件时间 |
| 2：三维书房 | 左键拖动平移、右键转向、滚轮缩放，点击书桌、座钟、纸张原位置 | 出现对应检查与记录；“物品列表（备用入口）”提供同规则操作 |
| 3：开关与盆栽 | 打开／推回抽屉，打开／关上窗户；点盆栽→“提起内盆查看” | 开关可逆；提起内盆只露出内部，不自动得到线索 |
| 4：实际查看 | 查看露出的外盆内部，再放回内盆 | 取得“窗边盆栽的内外盆”，放回后材料保留 |
| 5：问询入口 | 在人物问询选择玛丽或牧师，也可从人物档案进入 | 出现对应人物的提问区，当前人物明确 |
| 6：自由问询 | 向牧师问“你为什么离开寓所，回来时发生了什么？”，根据实际答复追问“然后呢？” | 答复保存为本人记录，连续接话。没有取得预期材料时保留原问题，再用固定备用补齐 |
| 7：固定备用 | 选择牧师，展开“固定问答与材料笔记（备用）”，点“询问：座钟平时准吗？” | 取得“牧师谈座钟”；已完成的一次性问题可能不再显示，材料保留 |
| 8：材料出示 | 向相关人物勾选已取得材料并提问，再切人物查看记录 | 保存本轮实际出示的名称和答复；不会自动向其他人物出示 |
| 9：专业核查 | 在警方固定区取得医生初查意见，申请核实医生到场与初查记录 | 显示预计时刻；通过“整理并等待”推进游戏时间，到时取得结果。现实等候和刷新不会完成办理 |
| 10：安排会面 | 按整案流程取得雷丁首供，再到警方安排与安妮正式会面 | 安排后出现交谈入口，安排本身不自动生成证词 |
| 11：树林场景 | 地图点“前往树林”→“沿小径走向空地”→“走近倒木旁” | 到达可检查位置；进入或拖动镜头不自动得到样本 |
| 12：实地采样 | 点倒木旁落叶→“拨开落叶查看”，再实际查看棕色小碎块 | 拨开只显露碎块；实际查看才取得“树林现场：棕色晶体样本”，地上碎块随后移除 |
| 13：跨地点问询 | 在树林打开人物问询与人物档案，再点上方“返回牧师寓所” | 已认识人物标明当前无法当面交谈；返回后恢复入口，已安排人物保留 |
| 14：样本辨认 | 返回后向警方交送样本，请海多克辨认，按预计时刻等待 | 取得初步意见，不将外观观察自动当作化验定论 |
| 15：保存与稳定性 | 反复往返书房／树林，切页、刷新后回看成果 | 不误报浏览器不支持WebGL；材料和操作状态保留。真实画面中断时“重试三维画面”不重新开局 |

模型的正文、披露或供述依据不合规时仍可能被拒，原问题与失败记录保留。仅辅助焦点缺失或摘录不符会自动降级，不再因此整段拒绝。答复通过结构检查后仍须核对事实，不等于内容必然正确。

## 整案推理与结案

按[整案跑通与验收流程](../frontend/full_case_walkthrough.md)第1—12节补齐取证：首供、独立证人、医学与枪械、供述变化、阿彻住处、纸张、视线、来电来源和树林样本。该文档逐步列出实际按钮、前置条件和检查点；已取得的材料不用重取。

1. 打开“推理与复盘”，选择怀疑的责任人物，引用实际用于本次论证的1—50份材料，填写10—1000字解释。
2. 点“提交推理评审”，确认保存原文、引用和反馈，此时不直接公开作者解答。
3. 显示“继续推敲”时，按反馈补查、修改后再提交，历史评审仍保留。仅猜姓名或罗列材料不保证通过。
4. 最近一次评审成立后，明确点“确认本次推理成立并结案”，显示“推理已结案”，复盘对照本次论证与作者重建。
5. 刷新或从首页继续同一调查，评审与结案保留；继续补查不会改写已经冻结的复盘。

单独验收提前查看解答时，另建测试调查并明确勾选放弃推理。预期为“已查看解答／本次未计为破案”，与正常结案分别记录。

## 异常记录与测试代码

发现问题时保留原调查，记录案件修订、当前地点、所选人物、原问题、实际出示材料、提示和操作顺序。

后端测试在 `backend/src/test/scala/`，前端单元测试在 `frontend/src/`，浏览器测试在 `frontend/tests/`。`tools/verify_*_live.mjs` 是开发验收工具，部分包含解答并会真实调用模型，不是普通玩家提示。
