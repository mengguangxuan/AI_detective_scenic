# 整案跑通与验收流程

适用版本：`vicarage_study/20`，含最新的整案状态提示。入口：[本机游戏](http://127.0.0.1:5173/case)。启动与模型配置见[验收准备](acceptance_preparation.md)。

这是一条覆盖当前主要功能及全部已实现核查项目的**全面验收路线**，不是玩家通关必须逐条完成的清单，也不是唯一调查顺序。文中包含取证路径、证词变化和局部时间核对提示，会降低探索难度；不提供凶手名单、完整手法或可照抄的结案推理。

按顺序跑即可；已有进度时，找到自己尚未达到的“检查点”继续，不重复取得已有材料。操作成功后会自动保存；建议每段结束打开线索整理核对一次，再刷新检查恢复。尚未发送的聊天或推理草稿不保证刷新后保留，先完成提交或自行留存。

## 0. 开始前

1. 刷新现有网页，打开“案件简介”。若是旧修订且需要体验新增内容，点右上角 **新建调查** 并确认，进入当前修订20。原调查保留在服务器；当前没有选档界面，不要用清浏览器数据或清数据库的方式重开。
2. 若当前调查已经结案或主动查看过解答，可以继续取证、回看结果；要重新测试“修改推理→再次评审→正常结案”，需使用一份尚未结束的调查，必要时另建。
3. 前往人物档案和地点地图，了解公开人物及相对位置。浏览、切页和刷新不会推进案件时间。地图不是传送入口；本版可直接操作的3D现场是书房，外出核查通过警方页面办理。
4. 模型配置正常时可以自由问询并提交推理；模型不可用时仍可按下文固定入口取证，但**不能把主动查看作者解答当作正常破案**。

### 操作位置约定

- **人物固定区**：人物问询 → 上方选择“与某人交谈” → 展开“固定问答与材料笔记（备用）”。换人后核对当前人物。
- **警方固定区**：警方交流 → 展开“固定问答与材料登记（备用）”，在“向警方了解情况”中找对应按钮。
- **安排／申请**：警方页的“调查安排”“核查进展”，不在固定问答折叠区。
- **补充问询准备**：人物页选择雷丁或安妮后出现的主面板，可展开“查看准备条件”。它与下方固定备用区是两个区域。
- 表内“取得”均指材料实际进入**线索整理**。有一句自然答复不一定已登记材料；固定问题取得后通常消失，已记正文仍可回看。
- 表内固定“出示……”按钮会执行该项材料出示，不必再去聊天框重复勾选。自己仅有材料不等于已经向对应人物出示。

### 办理时间怎么推进

申请后先看核查卡片的预计完成时刻。可以继续其他调查，也可以点页面上方 `整理并等待5分钟` 或 `整理并等待15分钟`。10分钟可用两次5分钟，20分钟可用15分钟加5分钟；已经完成就不必再等。**现实等候、切页和刷新不会让核查完成。** 结果完成后自动进入线索整理和日志，不需要再点一次“领取”。

## 3. 时间核对：测试局部阶段闭环

这里核对的是周四案发时段的记录，不是填写页面上方周五调查时钟的当前值。进入“线索整理”的“我的时间核对”：勾选 `座钟读数`、`牧师谈座钟`、`玛丽的时间依据`，填写换算时刻、选择“我的判断”，点 `提交核对`。此处是玩家自己的核对，不需要把所有材料勾上。

## 13. 自己形成推理并提交评审

先到线索整理，对照最初观察、独立证言、首供／补供及核查结果，再打开[推理与复盘](http://127.0.0.1:5173/conclusion)。

1. 选择你怀疑的责任人物，可多选。不要因为材料多就把所有候选人物全选。
2. 只引用真正用于论证的材料，**1至50份**。这条全面路线可能获得超过50份材料，不应全勾；重复登记类材料也不必全部引用。取得材料与在本次提交中引用是两件事。
3. 填写 **10至1000字** 的自己的解释：谁实施、谁配合、动机、主要经过、时间冲突、证据怎样支持，以及哪些仍是假说。列材料清单或猜中姓名不等于论证完整。
4. 点 `提交推理评审`。每次原文、引用、结果与反馈分别保存；此时不应该公开作者解答。
5. 若显示“继续推敲”，根据反馈补查或改写；可以用 `以第1次推理继续修改` 一类按钮带回那次原文，再重新提交。不要为了过关把没有核实的细节写成已证事实。
6. 若显示“核心推理成立”，应出现“待确认结案”。此时仍可继续调查，作者解答仍未公开；保存并刷新后状态应保持。

模型按你的文字和实际引用进行判断，**本文件不保证点完前面按钮就必然成立，也不提供照抄的正确解释**。若反馈要求本局不存在的化验或自行断言未取得事实，请保留本次记录，作为模型质量问题反馈；不要临时编造报告来满足它。

### 评审结果如何处理

| 页面情况 | 怎么继续 | 如何判定问题 |
| --- | --- | --- |
| “继续推敲” | 看检查项与反馈，补材料或修改论证后新提交 | 需要判断它指出的缺口是否真实、是否忠于已引用材料 |
| “评审暂不可用”／“评审未完成” | 原文已保存，尚无有效判断；稍后用新的提交再次评审 | 不算已破案，也不等于推理被判错误；模型仍可能输出非法引用 |
| 网络中断、“用原请求重试” | 先重试原请求，或刷新后继续原请求 | 未决请求不能换内容覆盖；已经成功的重试不应多记一次评审 |
| 成功记录了一次失败后，再点原请求重试 | 应返回该次原结果 | 原请求重试不是要求模型重新判断，想再评审应在界面新提交 |

**检查点13**：至少一次真实评审记录可回看。验证“修改→再提交”时，早期原文和反馈仍在；正常通关需要最新一次成为“核心推理成立”，不是用主动查看解答代替。

## 14. 明确结案、对照复盘，再继续补查

1. 推理成立后点 `结案并查看复盘`。切页时的 `前往结案选择` 只是导航，不会自动结案。
2. 九页顶栏均应显示“推理已结案”，进度区为“本次推理已结案”，不再仍以“当前阶段 · 书房初查”作为当前目标。
3. 复盘中有最后一次推理原文、怀疑人物、引用材料及作者解释；下方六个主题逐项列出证据边界和**结案时已取得**的相关材料。
4. 展开几份正文，核对“末次已引用”／“结案时已取得，末次未引用”是否与最后一次提交一致。作者解释不是自动给你的新线索。
5. 刷新，切换人物、警方、现场、日志等页面，再用 `查看结案复盘` 返回。案件时间、调查记录与结案结果应保持；导航本身不多写记录。
6. 如还有没问过或没检查的内容，可继续取得一份新材料；新材料应正常保存，原结案时的对照清单不回填，旧推理与反馈不被改写。若本轮已取齐，不需要为这项重置存档。
7. 可按[验收准备](acceptance_preparation.md)，在项目根目录的Windows PowerShell中用 `.\tools\backend.ps1 stop-serve` 正常停止本项目后端；等待原后端进程退出后，再用 `.\tools\backend.ps1 serve` 启动，看到HTTP ready后刷新。不用停原前端，不清身份或数据库。核对同一调查与复盘恢复。

**正常终点**：“推理已结案”，原提交与复盘可回看，继续取证仍保留这一结果。这里完成的是玩家推理，不会自动演出警方抓捕、人物再次认罪或原著未来事件。

### 主动查看解答的另一个终点（单独验收，含完整剧透）

若只想检查复盘布局，可以另开测试调查，取得任意材料后，展开 `提前查看作者解答（含剧透）`，明确勾选 `我选择放弃本次推理并查看完整解答`，点 `放弃推理并查看解答`。顶栏应为“已查看解答”，进度区明确“本次未计为破案”。

这条路径即使没有提交过推理也可使用，界面应说明没有原文；它会结束本次推理，不能再在这一局测试新的评审。请与正常成立后的结案分开记录。
