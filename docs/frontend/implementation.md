### 距离完整案件还差的主线步骤

1. **核查后的补充问询已完成。** 修订9支持本人实际收取材料、回应质询、明确开始、实际形成补充供述并与首供对照；下一步进入核心取证，不因改口直接判无辜。
2. **补齐核心证据与后续取证。** 逐项建立现场材料、纸张、座钟、声响之间的证据联系，接入后续重要信件和警方调查结果。以本局阶段、已知信息和玩家有效介入决定事件；有保护或取证阻断时不能强行照原著发生，也不预先下发未来报告。玩家能提出解释，还需要实际取证支持。
3. **完成指控、评分与复盘。** 玩家提交人物责任、动机、手法和证据链，后端按固定案件与已取得证据判断正确、错误或证据不足；结案后开放真实经过、人物秘密、遗漏线索与改进提示。最后完整跑通新建、调查、问询、取证、指控、存档恢复和复盘。

以完整可结案主线作为下一完成目标，次要支线与界面细节随后补充。当前没有给出百分比或固定工期；每块仍包含材料制作、规则校验和验收，不能仅以人物是否出现判断完成。

### 鼠标与物品操作

- 鼠标左键拖动平移，右键拖动转向，滚轮缩放；触屏单指平移、双指缩放／转向。镜头有目标范围与角度限制，点选物品不再自动改变观察中心。恢复全景单独重置镜头。
- 点击模型本体即打开场景内物品菜单，拖动超过阈值不会误触。关闭按钮、Escape或点击空白可关闭菜单。菜单在窄屏中重新限制位置与高度。

- 展开的“物品列表（备用入口）”用于键盘、无WebGL或无法准确点选模型时调查，不承担选择镜头中心的职责。

### 逐物品登记与执行边界

`scene.objects` 为本场景的物品登记：稳定节点ID、实体ID、名称、可选调查点及点击即读的路线。调查点关联同一案件数据中的常见操作、状态前提和结果，避免在前端另写一份授予规则。

每个可交互模型通过 `SceneItem` 取得其登记；缺失登记使场景加载失败并显示备用入口。发布加载器检查已关联实体的节点登记覆盖、节点／实体重复、入口匹配以及阅读路线是否属于该物品。纯装饰几何不作为可交互物品。添加模型时须同时登记外观或可执行入口；不能根据名称猜测能力。

玩家视图只带当前合法操作及已经取得的物品正文（`points.findings`）。开关、阅读和时间核对仍经后端权限、条件、序号与同事务回执校验；镜头平移不会改变服务端玩家位置或授予新权限。未决的自动阅读与核对请求同样先保存原载荷，刷新重试复用原编号。

### 自然文案与玩家核对

- 物品材料只呈现既有读数、状态、原文摘录和来源；删除“钟面读数不等于死亡时间”等预设结论和规则说教。
- 固定证词改为人物自己的说法；不确定的回忆用“具体几分我记不清了”等表达，不把本来明确的证言全部改成不确定。
- 初始阶段目标与线索标题不公布时间矛盾的答案，删除原先写明正确结论的按钮。
- “我的时间核对”让玩家从已取得的材料中选择依据，填写换算时刻并选择自己的判断。默认不选择判断，也不预填时刻。
- 新 `CompareTimesMessage` 负责核对。正确答案与必要依据保留在服务端 `TimeComparisonSpec`，不进入快照。失败不返答案、不写调查记录；成功才保存玩家核对、引用材料与阶段完成状态。核对用专门的路线ID记录，维持原数据库日志约束；不能通过普通 `InvestigateMessage` 直接取得结论。
- 出示材料后的追问仍可使用，但不再要求玩家点完每个出示按钮才允许完成阶段。整体仍是固定问答和单一预写核对，尚无自由文本推理评分、AI或后续剧情。

## 身份与存档

后端生成随机本地凭证，以 HttpOnly、SameSite=Strict 的 /api Cookie 返回。accounts 服务保存凭证 SHA-256 摘要并解析可信 UserId；games 服务继续核对会话归属。API 不接受浏览器自报 userId，不开放案件导入／文件路径接口。HTTP 仅监听127.0.0.1，检查 Host、Origin、JSON 类型、自定义请求头、请求字段和长度，不开放 CORS。此边界用于本机课程演示，不是公网部署认证方案。

联网数据库为 backend/target/web-demo/windows/db-v1.mv.db（Linux 对应 linux）；与旧 CLI 演示数据库隔离。启动时只导入新的 browser_investigation.json，不修改旧案件修订或清空存档。四张业务表保留，另加 accounts 的 local_identities 技术表存演示凭证摘要。

浏览器只保存新的会话记录 detective-scenic:server-session:v2：会话编号、是否等待新建完成，以及未决请求的原编号、载荷和确认序号；不保存线索正文或权威现场状态。按用户明确授权，早期网页 Demo 进度已重置；前端清除旧 v1 会话定位与预览键，只使用当前存档。清除 Cookie 会丢失演示身份；页面不会因此悄悄覆盖原会话，可以明确选择新建调查。新建保留原数据库会话。

请求发送前必须先保存原载荷。响应不确定时保留原 RequestId 和 expectedSequence，包括刷新页面后重试；已确认成功但视图读取失败时只重读视图。客户端拒绝较旧视图覆盖较新状态，并检查会话与案件修订一致。服务器在会话行锁下投影一致视图，状态、调查记录和成功回执仍同事务提交。

## 课程组织与接口对应

- index.tsx 明确展示场景、检查、线索和记录；页面 types、纯函数、hooks、存储适配和组件就近组织。
- apis/accounts 与 apis/games 按服务组织。5 个公开消息对应5个前端 API 类；输入、响应解码就近，发送和错误处理在 apiClient。
