# 验收前准备与启动步骤

适用于当前 Windows 本机版本。项目目录：`D:\2026autumn\software_making\detective_scenic`。

日常验收按下面的步骤启动即可，无需重新安装依赖或修改系统环境。

启用自由问询前，先完成本文第8节的模型接口配置；未配置时仍可使用固定问答。

## 1. 先检查是否已经启动

- 查看之前打开的 PowerShell 终端：后端是否仍显示 `[HTTP ready]`，前端是否仍在运行 Vite。
- 如果两者都在运行，直接打开或刷新 [现场探索](http://127.0.0.1:5173/scene)，不用重复启动。
- 如果只运行了一端，就只启动缺少的那一端。关闭网页不会停止服务，关闭运行服务的终端则可能停止服务。

不能仅凭上一次验收成功判断服务仍在运行。下面两个终端都使用 **Windows PowerShell**，可以在 VS Code 中新建 PowerShell 终端，也可以从开始菜单打开。

## 2. 终端一：启动后端

复制执行：

```powershell
Set-Location 'D:\2026autumn\software_making\detective_scenic'
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\backend.ps1 serve
```

等待出现：

```text
[HTTP ready] http://127.0.0.1:8080/api/
```

实际输出后面还会带数据库路径。看到 `[HTTP ready]` 才表示网页后端已经就绪；只看到 sbt 启动或编译信息时还需要等待。

**保留这个终端运行。** 后端负责调查状态、线索、问答记录和存档。

这里使用 `serve`。`run` 是命令行演示，不会启动网页所需的 HTTP 服务。

## 3. 终端二：启动前端

再打开一个 PowerShell 终端，复制执行：

```powershell
Set-Location 'D:\2026autumn\software_making\detective_scenic'
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\frontend.ps1 dev
```

等待出现类似输出：

```text
VITE ... ready
Local: http://127.0.0.1:5173/
```

**这个终端也保持运行。** 启动器会使用 E 盘已有的 Node.js 和项目依赖，不需要另外执行 `npm install`。

上述命令中的 `ExecutionPolicy Bypass` 只作用于该次脚本进程，不会修改系统长期执行策略。

## 4. 打开页面，开始验收

建议始终使用 `127.0.0.1`，在同一个浏览器中验收，避免混用 `localhost`、不同浏览器或无痕窗口而切换浏览器身份与存档。

| 页面 | 地址 | 主要检查内容 |
|---|---|---|
| 案件简介 | [http://127.0.0.1:5173/case](http://127.0.0.1:5173/case) | 公开案情、阶段目标、调查进度与进入现场 |
| 现场探索 | [http://127.0.0.1:5173/scene](http://127.0.0.1:5173/scene) | 镜头、物品菜单、现场检查和开关 |
| 线索整理 | [http://127.0.0.1:5173/clues](http://127.0.0.1:5173/clues) | 已取得材料与时间核对 |
| 人物档案 | [http://127.0.0.1:5173/people](http://127.0.0.1:5173/people) | 人物身份、已获答复与选择问询对象 |
| 调查日志 | [http://127.0.0.1:5173/journal](http://127.0.0.1:5173/journal) | 搜索记录、顺序排列与新材料筛选 |
| 人物问询 | [http://127.0.0.1:5173/interviews](http://127.0.0.1:5173/interviews) | 提问、出示材料和查看已记录答复 |
| 警方交流 | [http://127.0.0.1:5173/police](http://127.0.0.1:5173/police) | 医生初查意见、警方现有情况和线索出示 |

打开根地址 `http://127.0.0.1:5173/` 也会进入现场页。页面顶部导航可以在七页之间切换。首次了解案件可以先打开案件简介，所有页面共用同一份调查进度。

进入后先确认：

1. 页面没有停在“正在连接后端”或报错状态。
2. 能看到当前案件和调查阶段。
3. 现场可以加载；等待三维画面出现后，再点击物品。
4. 在七个页面之间切换，案件与材料数量保持一致。

然后即可按需要检查本轮改动：

- 左键拖动平移，右键拖动转向，滚轮缩放；点击物品显示操作或内容。
- 在问询页询问牧师、玛丽，取得的答复会进入线索页。
- 在同一页面会话中切换页面，应保留核对草稿和现场视角。
- 刷新页面，应恢复后端已保存的材料、问答、开关和阶段状态。**未提交草稿与镜头位置只在切页时保留，整页刷新后可能重置。**

如果要从头验收，点击右上角“新建调查”并确认；如果要检查恢复，则保留当前会话，不要新建或清除浏览器数据。

当前演示范围是书房初查、固定问答、受限自由问询和时间核对；自由问询需先配置模型，后续剧情尚未开放。具体玩法与验收范围见 [实现说明](implementation.md)。

## 5. 验收结束后停止服务

### 停止前端

在运行前端的终端按 `Ctrl+C`；如终端询问是否终止批处理，按提示确认。

### 停止后端

在另一个空闲 PowerShell 终端中执行，也可以使用刚停止前端的终端：

```powershell
Set-Location 'D:\2026autumn\software_making\detective_scenic'
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\backend.ps1 stop-serve
```

该命令只请求本项目后端退出。等待原后端终端显示 `serve completed` 后，再关闭终端或重新启动。

正常停止服务不会删除调查存档。

## 6. 常见情况

| 情况 | 处理方式 |
|---|---|
| 浏览器提示无法访问5173 | 检查前端终端是否已启动、有无报错；未启动则执行第3步。 |
| 页面能打开，但提示后端连接失败 | 检查后端是否出现 `[HTTP ready]`；就绪后点击页面上的“重新连接”。 |
| 5173端口已占用 | 先检查是否已有本项目前端；有则使用现有服务并刷新，不再启动第二份。不要随意改到另一个端口。 |
| 8080已占用或数据库被占用 | 先确认是否已有本项目后端。需要重启时按第5步优雅停止，等待退出后再执行第2步。不要删除数据库或锁文件，也不要批量结束 Java 进程。 |
| 更新前端后页面仍像旧版 | 刷新当前页面，必要时按 `Ctrl+F5`；不要先清除 Cookie 或存档。 |
| 修改了后端代码或案件数据 | 先优雅停止后端，再启动 `serve` 并等待就绪；不要同时运行多个 sbt编译或在 Windows／WSL两边并行构建。 |
| 页面出现“用原请求重试” | 等连接恢复后点击该按钮。它会复用原请求，避免重复记入调查。 |
| 页面出现“重新读取视图” | 操作已经保存，只需点击重新读取，不必再做一次相同操作。 |
| 找不到 Node、Java或依赖 | 先运行下方诊断命令，保留报错。环境准备的详细说明见 [实现说明](implementation.md)，不必直接重装全部依赖。 |

环境诊断命令（只检查，不安装）：

```powershell
Set-Location 'D:\2026autumn\software_making\detective_scenic'
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\backend.ps1 doctor
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\frontend.ps1 doctor
```

后端启动日志：`backend\.build-cache\windows-serve.log`。如果启动失败，可保留这个日志及终端最后的报错，便于排查。

## 8. 配置自由问询的模型接口

### 首次准备配置文件

在项目根目录的 PowerShell 中执行。已有本地配置时不会覆盖：

```powershell
Set-Location 'D:\2026autumn\software_making\detective_scenic'
if (-not (Test-Path .\backend\config\model-api.local.json)) {
    Copy-Item .\backend\config\model-api.example.json .\backend\config\model-api.local.json
}
```

注意：`model-api.example.json` 只是模板，后端不会读取它。不要把密钥填在示例文件里；真正填写的是复制得到的 `model-api.local.json`。

使用 VS Code 等编辑器打开 `backend/config/model-api.local.json`，填写自己的密钥。示例格式如下：

```json
{
  "baseUrl": "https://api.deepseek.com",
  "apiKey": "在这里填写自己的密钥",
  "model": "deepseek-flash",
  "timeoutSeconds": 20,
  "maxTokens": 512,
  "disableThinking": true
}
```

| 字段 | 填写说明 |
|---|---|
| `baseUrl` | 服务基础地址，不包含末尾的 `/chat/completions`；使用兼容服务时可保留它要求的 `/v1`。 |
| `apiKey` | 服务提供的密钥，保存在本地后端配置，不填到前端代码或聊天消息里。 |
| `model` | 服务支持的模型名；本项目示例按DeepSeek当前文档填写，可自行替换。 |
| `timeoutSeconds` | 请求超时，允许2至60秒，建议先保留20。 |
| `maxTokens` | 本次结构化输出的上限，允许128至2048，建议先保留512。 |
| `disableThinking` | DeepSeek示例设为true，发送关闭思考模式的参数。若其他兼容服务不支持 `thinking` 字段，改为false以省略该字段。 |

配置文件必须是合法JSON，保留上述字段，不添加注释或末尾多余逗号。本地配置文件已加入Git忽略规则，示例文件不包含密钥。也支持用当前后端进程的 `DETECTIVE_MODEL_API_KEY` 环境变量覆盖文件中的密钥；未设置时直接使用文件内容。

### 保存后重启后端

配置在后端启动时读取。先按第5节优雅停止后端，等待退出，再按第2节启动 `serve`。前端仍可保持运行，刷新页面即可。

然后打开 [人物问询](http://127.0.0.1:5173/interviews)，选择“与克莱门特牧师交谈”或“与玛丽交谈”，在“你的问题”中输入问题，例如：

- 询问牧师：“你家的钟平时走得准不准？”
- 询问玛丽：“你凭什么记住上校到达的时间？”

可以勾选已取得的材料一同出示。对话提交成功后会保存到后端；刷新后重新选择同一人物可查看。两名人物的记录分别显示，材料不会自动向所有人物同步。

### 当前能力与失败处理

本版由模型依据该人物的自身经历、人物关系、实际出示材料和对话历史组织自然回答，不再只选择预写句子。模型同时返回本轮披露的材料ID，后端校验引用及前置条件后授予材料；普通身份解释和经历澄清可以没有材料ID。文字语义仍可能出错，结构校验不等于已证明每一句符合案情。固定问答保留为备用。

未配置、超时、鉴权失败或模型输出不合规时，页面显示系统提示并保存本次问题，不冒充人物已经作答。展开“固定问答与材料笔记（备用）”可继续原有调查路径。修好配置后请重新发送问题：已保存的原请求重试只返回原结果，不能把一次失败记录改写为另一条答复。

如果页面显示“用原请求重试”，按第6节处理；问询还在进行中时不要新开重复问题。服务器意外退出后，待约90秒的请求租约到期，可用原请求续接。服务端保证本局状态只提交一次；进程在调用外部模型后、保存结果前崩溃时，外部调用可能再次发生。

模型调用日志只记录配置状态、错误类别和HTTP状态码，不打印密钥、模型原始错误正文或完整提示词。出现401通常需核对密钥，429需检查服务额度或限流；更多情况按服务商文档处理。

格式依据：[DeepSeek首次调用API](https://api-docs.deepseek.com/zh-cn/)、[JSON输出说明](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)。独立调用接口在 `backend/src/main/scala/services/models/api/ChatCompletionClient.scala`，传输实现为同服务的 `utils/DeepSeekChatClient.scala`；填写上述配置即可使用，无需修改前端。


## 9. 案件简介、人物档案与独立日志验收

本轮只需刷新前端，无需重启后端或重新填写模型配置。

1. 打开[案件简介](http://127.0.0.1:5173/case)，查看公开案情、阶段目标和进度，点击“开始现场调查”或“返回现场调查”。
2. 检查一个物体，再打开[人物档案](http://127.0.0.1:5173/people)。只展示可接触人物的公开身份和你已取得的答复；没有问过的内容不应提前出现。
3. 点击人物卡片上的“询问某某”，进入问询页后应已选中该人物。可以用固定问答取得一条答复，再回档案检查。
4. 打开[调查日志](http://127.0.0.1:5173/journal)，搜索材料名称或记录内容，切换最早／最新在前，勾选“只看有新材料的记录”。普通开关记录仍保留在完整列表里。
5. 刷新日志页面，已保存记录仍在；搜索和筛选仅为当前页显示设置，不写入存档，离开页面或刷新会重置。
6. 返回线索页，日志已移到独立页面，可通过页末链接进入。当前仍只有书房初查阶段，没有新增后续剧情。

自由问询的重复回答／人物经历资料不足已记录为待改进项，本轮不把该问题列为页面验收的阻塞条件。


## 10. 警方交流与医生初查验收

当前案件修订为 `vicarage_study/4`，书房场景仍为 `study/4`；浏览器定位键为v6；已有v5调查会连同未决请求恢复，新建调查使用修订4，旧存档不会改写。后端已重启加载本轮内容，前端刷新即可；以后从头启动仍按前文步骤，不需重新填写密钥。

1. 打开[现场探索](http://127.0.0.1:5173/scene)，介绍应说明是周五保留现场、遗体已送交医生检查，而非医生尚未到场。
2. 点击“向警方询问医生的初查意见”，或打开[警方交流](http://127.0.0.1:5173/police)。直接输入“医生对死因和死亡时间有什么意见？”。也可展开“固定问答与材料登记（备用）”，点击“询问医生的初查意见”，取得两份材料：死因、死亡时间；医生说的是当时检查时已死亡半小时左右，不是一个精确的钟表时刻。
3. 可以继续询问遗体去向与现场保全、雷丁前夜的自首情况。这些是当前初查材料，不含未来验尸庭报告。
4. 回到现场取得一份材料，再到警方页勾选它，点击“向警方出示”。交流记录应保存具体材料和警方确认，已出示材料不再重复列入待选清单；出示不自动给新证据或推理答案。
5. 刷新页面，取得的医生材料、已出示清单及交流记录仍在。也可以在线索页和独立日志中回看。
6. 警方页默认是模型对话，按第8节配置使用；固定问答和材料登记收进备用折叠区，模型不可用时仍可走原流程。

按用户最新要求，本轮不增加遗体或血迹模型。更符合本案的现场痕迹表现已单独记入交互待办，留待后续处理。


### 更新后恢复调查报“服务暂时无法完成请求”

已修复修订3的旧调查恢复被误判为500的问题。修订3和4共用当前书房场景，旧调查继续绑定原材料／原修订，未决请求仍按原载荷重试。浏览器只在缺少v6定位时复制v5定位，并保留v5作为备份，不清除旧请求。

更新后先刷新页面，若还显示错误则点击“重新连接”。旧修订恢复后页面会提示其版本；要查看新增的警方内容，可确认后点击“新建调查”进入修订4。不要为了恢复而删除Cookie、浏览器数据或数据库。未实现的更早场景会给出明确版本提示，不再返回通用500。


## 11. 人物与警方自然对话验收

本轮不更换案件修订、浏览器存档键或密钥；正常后端已重启，刷新前端即可。修订3／4原有调查仍可继续。旧问询记录不重写、原请求重试仍返回原结果；要测试新回复请发送新问题。

- 牧师：连续问“斯莱克是谁？”“你说的病人是谁？”“你什么时候离开的寓所？”。应分别回应关系、阿博特先生、17:30来电后的离家经过；不能把预计18:30回来当成实际回家时间。
- 玛丽：问“你一直在家吗，有没有听到异响？”。应区分关键傍晚在厨房／应门、后来外出请医生，以及记得一声以为来自树林的响声。她不应凭空给出精确钟点或声响真相。
- 警方：打开 `/police`，直接问医生初查意见；勾选已获材料后问“你怎么看这份材料？”，再追问。对话与出示材料记录都应刷新恢复。警方不会自动读到牧师／玛丽的对话，只有实际出示才共享。
- 固定问答和旧材料登记在各页备用折叠区，原有记录保留。
