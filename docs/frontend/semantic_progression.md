# 实际答复的语义登记

适用：案件修订26，人物模板10／答复协议5。原25源文件按字节冻结，旧调查不升级。书房／树林场景及开局自由联系会面人物不变。

## 运行流程

1. 冻结本人知识、实际收到的材料、本人既有说法、最近对话与合法主张范围。材料有来源和作者声明的事实关联，不因出示自动变成客观真相。
2. 人物模型只输出实际发言和对话焦点，不负责发证据。它仍受本人知识、隐瞒策略和新说法条件约束，可以拒绝、怀疑、反问或坚持。
3. 在短事务中保存有效答复检查点；连接外调用独立语义核对器，识别本轮实际表达的授权主张及原文引用。核对器不接收人物私人档案或完整案件真相。
4. 后端复核主张权限、原文引用、实际收到的依据、本人原说法、请求租约与调查序号，再将主张、证据、日志和回执原子提交。
5. 后续调查读取实际已登记的记录。人物原话作为材料正文保存，旧供与新供分别存在，不用后来的措辞改写原材料。

角色模型如果仍附带旧式披露ID或更新字段，这些标注在新协议中被忽略；不会据其发证据，仍须独立核对实际发言。焦点字段失效可从原话降级，不因此丢弃有效答复。保留模板7—9分支以恢复开发期冻结请求，当前新请求用模板10消除旧字段说明冲突，并强调物品与说话人的归属，已知历史转述错误不得当作事实继续扩写。

## 两种入口和同义材料

固定备用给出作者审核的答复与主张，和自由问询共用同一登记、权限及事务逻辑；不调用模型即可取证。固定按钮继续保留作者设计的材料配方，决定哪份备用答复可用。自由问询理解玩家具体提问和人物实际发言，不要求逐字复述或由人物自行填对ID。

同义是核心主张一致，不要求台词相同；同样材料也不保证人物必定改口。特别区分“某人声称自己开枪”与“某人真的开枪”、近似医学意见与精确时刻、收到材料与相信材料。

材料跨入口都登记本人实际收到的原文。作者明确将不同记录关联到相同主张时，可通过共享事实引用满足同一调查条件；实际出示记录仍指向真正那份材料，不虚构收到另一个ID。不会仅凭标题相似、关键词或向量距离擅自合并证词。普通原文如未由作者声明关联，不能据此保证任意两份材料自动互换。

## 失败、重试与存档

两次模型调用均不占用数据库连接或行锁。人物有效答复保存在原问询请求的可选draft中；核对服务／整体格式失败时不授予材料，释放本次租约并返回可重试状态。核对输出的附加解释不进入记录；分类标签无法确认时保留原话、不授予进展。个别登记项的引用、权限或依据无效时，仅丢弃该项，保留有效项与实际发言，并以unconfirmed标记提示尚未确认；不将它们当作通过，也不因此让整轮对话反复卡住。浏览器保留原请求，刷新后重试只对已保存答复核对，不让人物重新回答。

并发接续使用新的租约token；旧工作者、其他用户和修改原答复的请求不能覆盖检查点。调查已经变化时不将旧结果强行写入。网页在核对重试期间允许选择人物，异步结果会保留当下选择，不用请求开始时的旧选择覆盖，避免记录已保存但问询区消失。成功后原请求重试返回同一回执；不承诺远程模型在崩溃前尚未保存的调用恰好一次。

可选登记元数据存于原问询记录，旧记录缺省且编码省略；检查点存于原请求JSON，不另建数据库表或重放日志重建调查。未经检查的供应商原始输出不进入日志或玩家响应。

## 代码入口与当前范围

- `InterviewRules`：冻结角色上下文与版本分发；`SemanticInterviewPrompt`：角色发言。
- `ReviewInterviewMessage`、`SaveInterviewDraftMessage`：两步调用、检查点与恢复；`FinishInterviewMessage`：完成事务。
- `SemanticInterviewRules`：逐项语义核对及固定／自由共用登记；`SemanticEvidence`：作者明确声明的主张关联。
- `WitnessClaimRule`：开放文字描述新说法的依据条件，以稳定ID关联本人原说法。首批详细配置雷丁、安妮六个新说法，普通人物和警方复用通用登记。
- `RecordedInterviewRules`：保留实际说出口的第一份原文；`InspectInterviewEvidence`：本机只读查看登记与是否有答复检查点，不打印私人档案。

固定备用能够跑通，不代表任何自然问法都已语义正确。独立核对仍是模型判断，存在误解、漏记或误记风险；程序检查引用、授权和事务，不能证明全部自然语言含义。细微心理、无依据细节和材料说服力仍需真实抽样与人工检查。本轮不生成任意行动、现场物证、未来事件或新案件。

手动步骤见[当前指南](manual_test_guide.md)。`tools/verify_semantic_progression_live.mjs`通过公共API记录真实问答和识别结果，`--continue`只续接检查点中的原请求再继续样例，`--restore`核对完整快照与原回执。`--ownership`单独检查枪的来源追问，不与主样例缓存混用。完整新26取证／评审工具为`tools/verify_case_completion_live.mjs --semantic --positive`，失败回执保留，同一调查用`--semantic --positive --resume`新建评审请求。脚本含解答并实际调用模型，不作为玩家提示。

## 本轮真实抽样结果（2026-11-02）

正常TokenHub／DeepSeek已验证习惯换一种问法登记、固定入口收到的座钟原文能在下一轮读回、单问医学时间不连带发死因、安妮材料实际可读、取消勾选仍能承接收到的原文，以及普通枪来源追问不自动撤供。模板9曾误述枪归属，原话保留；模板10独立样本正确回答是本人所有，未知购买来源不补造。

主样例首轮明确撤供但核对未给出合规登记，保留原答复和unconfirmed，未补发线索。用`--continue --followup`在同一调查另问修正的具体内容与实际依据，雷丁新供、安妮撤供／来访新说法和警方区分两版供词均实际登记，依据来自已交到本人面前的材料。该成功是后续真实问答，不是偷偷重新评判或替换旧回执；漏记风险仍在。牧师曾补充未提供的约见理由，也是未解决的措辞质量样本。

新26固定备用取证到真实评审五项Established、明确提交Solved及六节冻结复盘已跑通。首次评审引导格式失败仍保留，同一调查使用新评审请求完成；不因模型失败重建调查。完整自动化与进程重启记录见[实现状态](implementation.md)。
