# 主站场景制作与预览

2026-11-04。入口：案件区的“进入场景制作”，或 http://127.0.0.1:5173/create-scene 。

本阶段完成作者制作与私有预览。保存的场景尚未接入玩家调查，不会自动发布案件，也不授予线索。

## 操作步骤

1. 填写制作名称、目标场景编号，以及原始资料、时代、当前阶段、必须保留的事实／空间关系、期望氛围。也可以导入已有作者JSON；未知字段、嵌套内容保留。资料内有places时，从其稳定ID选择目标地点。
2. 点“保存草稿”。原始资料保存到后端，这一步不调用模型。制作记录按当前本机身份隔离；刷新后可继续。
3. 点“开始模型制作”。输入冻结，DeepSeek直接读取作者字段，先审核资料是否充分并提出布局。缺口显示在检查意见中，不由程序补造事实。
4. 查看模型布局俯视示意及制作说明。示意图只表达预留范围，具体形体尚未生成。点“确认布局并生成3D场景”后，才开始模型部件和组装器编写。不同意时复制为新草稿，修改原始字段并重新提交。
5. 任务面板的“刷新制作状态”只重新读取当前记录，不重发制作请求；网络恢复或页面曾停在旧状态时可使用。后台进行代码／运行检查、实际浏览器截图、独立视觉审核、另一个新上下文的整体复核及反馈修正。主站分开显示运行检查、视觉审核、整体复核和处理轮数。
6. 运行检查、视觉审核与整体复核均通过后，才显示“查看3D预览”和独立预览链接。预览可切换模型视角、拖动查看和检查模型登记的动作。
7. 点“保存私有场景”，将通过的源码、计划、原始字段、程序检查和实际截图／审核记录另存。以后从“我的制作记录”打开。只有任务定位保存在浏览器；服务端保存资料和状态。

需要补资料时，保留原任务及意见，复制为新草稿后修改。调用失败且未达检查／调用上限时，可点“继续未完成的制作”：保持同一任务、原始字段和已确认布局，匹配完整历史返回后重新检查并复用，只为剩余步骤调用模型。不会将截断片段当作成品复用。达到上限时保留任务，不自动清零；重新提交新草稿会产生新的模型调用。当前最多10轮检查、88次文本调用，累计token仅记录，不设累计保护上限。未通过任务不开放正常预览；此前独立实验的作者静态查看不等于验收通过。

## 代码与运行边界

- `frontend/src/pages/SceneProduction`：填写／导入、制作记录、布局确认、状态和私有预览。`frontend/src/apis/sceneproduction`与后端公开消息一一对应。
- `backend/src/main/scala/services/sceneproduction`：原始字段验证、作者权限、H2草稿记录、制作启动、布局确认和成品保存。各项制作等待均在短事务之外。
- `services/models/api/ChatCompletionClient.scala`：供应商出站调用入口。`SceneModelBridge`为本机运行器提供私有临时凭证接口，复用该模型服务；浏览器及制作运行器不取得供应商密钥。场景代码响应有独立的有限长度／输出额度，人物问询原有限制保留。
- `tools/run_scene_pipeline.mjs --production <任务目录>`：每项任务的独立进程和随机本机端口，接受原始作者字段；确认布局前暂停。特定布局、模块、组装器、审核和修正全部调用DeepSeek，宿主只提供通用契约、提示词和检查。
- 当前运行类型：`tools/scene-pipeline/types.ts`。统一定义、模块交付、校验与提示词的待实施方案见[场景制作共享契约整理](scene_runtime_types.md)；其中拟统一内容尚未修改运行代码。
- H2表`scene_productions`保存归属、输入、阶段与时间。制作文件在`backend/.build-cache/scene-production/<UUID>`；成品在`backend/target/scene-artifacts/<UUID>`。两处均为本机私有生成数据，不提交版本库。不要清理这些目录作为恢复手段。
- 开始制作使用独占启动标记，重复提交不自动重发付费生成；发生不确定启动故障时保留现场。显式续作按已有调用次数保留独占恢复标记，防止重复启动；短事务核对作者后再启动进程。预览进程重启只加载既有结果，不重新生成。后台生成期间停止整个后端可能导致正在进行的模型请求失败；原任务保留，不自动重发，按失败状态显式继续。
- 当前是本机单机演示，不是正式多用户部署。预览有独立来源、访问凭证、HttpOnly cookie和内容策略；代码筛查不等同于通用不可信代码沙箱。外网部署还需要正式身份、隔离执行和任务调度。

## 模型错误排查

新的制作进程会将模型错误区分为输出未完整结束、HTTP错误、格式异常、超时等；具体诊断保存在任务私有`requests/*.failure.json`。截断片段只供诊断，不作为场景执行。早先只记录`model service unavailable`的失败无法事后补回未保存的供应商返回。

维护时可通过`tools/backend.ps1 diagnose-scene -ProductionId <UUID> -ModelRequestNumber <N>`对已停止任务的某一原始文本请求做一次诊断。**这会产生一次真实DeepSeek文本调用**，先保留调用记录且不自动重试；返回只保存，不执行，不会恢复整条制作流程或调用3D生成模型。运行前仍须按项目规则停止后端，完成后恢复。不要为绕过独占标记而删记录。

## 验收

- `tools/backend.ps1 test`：权限隔离、超过原8192字节的作者字段、冻结输入、布局确认、未通过保存拒绝、重复保存、文件数据库重连；模型图片和较长代码响应；已有调查回归。
- `node --test tools/scene-pipeline/production.test.mjs tools/scene-pipeline/policy.test.mjs tools/scene-pipeline/contract.test.mjs`：原始字段送达、布局暂停和确认幂等、私有预览凭证／门禁、动作及父子关系协议。使用本地假模型，不消费供应商额度。
- `tools/frontend.ps1 browser-test -TestFilter 'scene authoring'`：主站导入未知字段、保存、刷新、布局、审核后预览、成品保存与窄屏展示，模型状态采用测试替身。
- 主站与后端启动后执行`node tools/verify_scene_production_live.mjs`；停止并重启后端，再执行同命令加`--restore`，验证真实主站／文件数据库草稿恢复。这项不开始生成、不调用模型。测试身份与快照仅保存于忽略的缓存目录。

这些检查验证接入流程与权限，不代表再次验收了真实模型的场景质量。本阶段未新增真实模型调用；此前独立实验仍保留其原审核状态。
