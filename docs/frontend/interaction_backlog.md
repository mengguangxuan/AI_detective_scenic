# 场景交互实现状态

## 2026-10-28 最新验收反馈

本节保留用户对原著案首阶段的试玩要求。后续已按这些要求实现，当前状态见下方实施更新；具体需求仍作为验收依据。

### 1. 鼠标直接移动视野

- 支持用鼠标拖动平移视野，保留必要的旋转与缩放；不再要求玩家先用文字按钮选择观察中心。
- 点选物体主要用于操作和查看信息，不应每次都强制重置玩家刚调整好的镜头。恢复全景可保留为辅助功能。
- 实施时明确手势提示，区分点击与拖动，避免平移结束误触物体；限制镜头范围，避免穿墙或完全丢失现场。
- 镜头平移本身不改变玩家在后端的位置、调查权限或案件进度；真正的角色移动另行设计。

### 2. 点物品就出现其常见操作

- 点击模型本体即可呈现对应操作及信息，不要求先找编号，再滚动到页面下方的“现场检查”。文字入口保留为辅助和无WebGL时的替代入口。
- 抽屉显示当前可用的拉开／推上；窗户显示开／关；可阅读的信或纸张点击后展示获准内容。原著案的纸张原件已由警方保管，点击原位置只能查看相应摘录，不能冒充原件。
- 制作、登记每个物品时，同时记录稳定实体／节点ID、信息入口、支持的常见操作、状态要求和操作后的表现。场景绑定与操作清单一同检查，避免模型做完却遗漏交互。
- 操作从已有登记中关联，不根据物品中文名称猜测能力，不穷举现实动作。已登记且当前合法的操作由后端玩家视图提供，前端负责就近显示菜单和动画，不能自行授予证据或更改权威状态。
- 窗户当前只有普通观察，尚未实现开关；实施时需补齐状态、后端规则、表现与恢复，不能仅加一个无效按钮。
- 验收覆盖点击本体、菜单位置／关闭、操作状态切换、重复请求、刷新恢复，以及拖动镜头时不误弹菜单。

### 3. 文案自然，只提供事实与人物自己的话

- 证词使用符合人物身份的日常说法。例如用户要求将生硬的“不能保证……”改为适合语境的“我也不确定……”。不能机械替换全部限定语，更不能给原本明确的证言凭空添加犹疑。
- 物品检查只提供有案件设定依据的读数、状态、痕迹和来源。例如座钟记录发现时的18:22及停止、倒下的状况；快十五分钟的习惯由相关人物讲述。历史初勘所见与玩家当前所见仍需区分。
- 删除线索中替玩家作推理的说教，如“钟面读数不等于死亡时间”“不能据此排除嫌疑”等。规则和信息边界保留在制作文档与后端校验中，不由每件物品或每名证人重复宣讲。
- 没电、血迹等只是用户举的物品状态例子，不因此给原著案增添这些设定；未设定的信息不补造，已经明确的物品信息也不能为制造难度而省略。
- 同时检查阶段目标、按钮、线索标题、普通观察、问答与阶段提示。当前目标和“记录结论：座钟不能直接确定死亡时间”按钮已经提前给出答案，需随推理交互一起调整，不能只改证词正文。
- 比较时间及得出结论留给玩家；后端仍校验其引用材料与状态，不能以点完预设问题、接受系统现成答案代替玩家判断。

### 下一小步建议

先修订当前书房阶段的交互与文案，再由用户验收；暂不扩展后续剧情或接入AI。依次补物品交互登记与后端状态、接入拖动平移和物体操作菜单、重写自然证词并移除提前给答案的提示，最后沿原调查路径验收权限、存档和操作恢复。此顺序是本次反馈后的建议，不是已经完成的功能。

## 自由问询反馈与优先级（2026-10-28，待改进）

用户实测反馈：模型经常重复几条相同信息；例如问牧师“你什么时候离开了寓所”，无法给出对应回答。当前实现让模型选择有限的作者答复ID，人物经历资料不完整，超出条目的问题无法真正展开；这不只是提示词措辞问题。

用户明确要求先记录并继续推进，模型回答质量不是课程重点。本轮不扩大答复库、不继续调提示词或更换模型，不把有限预写证词的匹配描述为完整人物扮演。以后统一补人物自身时间线、知识与可披露边界，再处理上下文相关回答和重复问题；仍不得把整案真相发给每个人。

开发优先级转回课程可演示的页面与完整流程。下一小步补案件简介、人物档案、独立调查日志，复用已有后端公开视图；随后推进案件后续调查与结案流程。当前记录不代表自由对话问题已修复。

## 自由问询与固定追问的语义等价性（2026-10-30，用户明确暂缓）

用户实测：表达同样含义、出示相同或同义材料时，自由问询和补充问询固定按钮的推进效果不同。用户要求记录，先继续其他案件功能；本轮不修改这套机制。

已核对实现：固定按钮一次登记预设材料出示、固定回应和对应路线；自由问询成功后记录所出示材料，但“关键追问完成”依赖模型返回指定disclosureIds。程序不独立判断回答正文与标注的语义一致性，也不识别不同证据ID之间的语义等价关系。阶段由配置中的前置材料、指定回应和显式开始操作推进，不是模型根据整段对话语义自主判断。

待后续处理：让等价的实际调查行为产生一致的调查进展；区分“收到材料”“回应了关键问题”“形成新供述”，核对正文与结构化记录，保留可审核的依据、人物权限和历史版本。需要真实语义样例覆盖同义提问、漏标和误标，不能仅以模拟供应商返回指定ID通过宣称解决。具体诊断根因仍需用户对应问询记录，不能把这次差异武断归为某一轮漏标。

本条属于待办，不是修复声明；手动指南中的固定路线只用于明确测试路径，不代表两种入口已经语义等价。

## 玩家亲自发现现场线索与小型树林场景（2026-10-31，用户认可方案、暂缓制作）

用户希望现场线索主要由玩家观察、寻找和检查取得，避免所有调查变成警方申请后领取材料。专业辨认、实验、外围查访仍可交警方处理。时间紧，本轮先记录方案，继续后续功能，不启动树林3D制作。

最小范围为一小段林间小径和一处空地：从地点地图进入，复用少量树木、灌木和地面，提供返回入口；玩家根据听闻选择前往，通过观察和近处检查发现晶体，再申请海多克辨认。不制作开放森林，不依赖极小热点、随机刷新或装备背包增加难度。需支持文字备用入口，与3D检查共用同一后端规则，不在前端自行发材料。

实施时先补第二场景的进入／返回、稳定节点／实体／调查入口绑定，再制作模型与检查交互，最后验证跨页、刷新、请求重试、实际重启和低性能设备。地图浏览不冒充角色移动，检查结果不冒充物理模拟。现场发现与专业辨认分别记录；有依据的现场事实通过实际检查取得，不自动加入原著后续相遇。

修订15的警方树林查访是当前可玩过渡方案，不是最终探索体验。未来调整发现途径须发布新案件修订，保留旧调查的结果、请求及回执；不得覆盖已发布修订。优先完成推理提交与复盘，再回到这项探索体验补强。


## 推理提交后的评审、引导与结案（2026-10-31，修订17已实现）

用户明确否定“第一次提交即看作者答案”的收尾，要求独立模型知道完整真相，先评审玩家实际解释，给克制引导，允许继续调查和反复修改。评审与NPC角色扮演分开，复用模型传输设施，不能向普通NPC灌入全案真相。

修订17已实现判断与引导两步模型、逐次原文和反馈、失败不误判、成立后单独结案、主动放弃的独立结果。取消新流程的材料覆盖分，不要求目前无法取得的证据。旧修订16结果保持。流程与权限自动验收通过，真实模型反馈的语义与不剧透表现仍需实际验收；两组真实反例脚本目前因自动审批要求具体供应商授权尚未执行。
